## BINDING AMENDMENTS (resolve the critic's blockers; these override anything above or in the stream files)

Decisions made by the integrator on 2026-09-25. Streams must code to these.

1. **Save ownership.** `MeterManager` gains `var onRecordingStopped: ((Session, AutoStopRule.Reason?) -> Void)?`. EVERY stop (manual Stop button, auto-stop rule, notification action, `discard: false`) goes through `MeterManager.stopRecording(discard:reason:)`, which invokes the hook. `WattBenchApp.init` wires the hook to `store.save` (+ counters). Views never call `store.save` for a live recording. `SessionStore` gains `private(set) var lastSaved: SessionSummary?` so RecordBar can show a "Saved" toast keyed on `saveCount`.
2. **Reconnect.** No `Task.sleep` backoff. On an unexpected disconnect while `wantsAutoReconnect`, issue `central.connect(peripheral)` immediately and leave it PENDING (CoreBluetooth completes it whenever the meter reappears, including in the background). `ReconnectPolicy` only drives DISPLAYED state. `ConnectionState` cases are frozen as:
   `case bluetoothOff, unauthorized, idle, scanning, connecting(String), connected(String), reconnecting(name: String, since: Date), unreachable(String), demo`
   `.reconnecting` flips to `.unreachable(name)` after 120 s without a connection (a 1 s UI timer while `scenePhase == .active`; the pending connect is NOT cancelled while a recording is in progress). `retryNow()` re-issues `central.connect`. `forgetLastDevice()` cancels and clears the stored identifier.
3. **Journal time base.** `RecordingJournal` records are `(UInt32 t_ms, Float v, Float i, Float w)` where `t_ms` = milliseconds since the recording's MONOTONIC start (`ContinuousClock`), never wall-clock. Header (16 bytes): magic `"WBJ1"`, `UInt32 version = 1`, `Float64 startEpoch` (wall clock at start). On read: `timestamp = startEpoch + t_ms/1000`, `monotonic = t_ms/1000`. `Reading.id` becomes `var id: Double { monotonic != 0 ? monotonic : timestamp.timeIntervalSinceReferenceDate }` (Identifiable, Hashable). Write buffered every 1 s or 64 records; `synchronize()` every 10 s, on gap, on scenePhase `.background`, and on stop. Create the file with `FileProtectionType.completeUntilFirstUserAuthentication`.
4. **Chart data.** `ChartSnapshot.points` is RAW `[Reading]` (≤ 1200 = the 2-min window at 10 Hz). `Decimator` is used ONLY in Sessions detail and for sparklines. Signatures frozen in foundation: `struct DecimatedPoint { let time: Date; let min: Double; let max: Double; let mean: Double }`, `enum Decimator { static func minMaxBuckets(_ readings: ArraySlice<Reading>, metric: Metric, targetCount: Int) -> [DecimatedPoint]; static func yDomain(_ points: [DecimatedPoint], padding: Double = 0.05) -> ClosedRange<Double>; static func window(_ readings: [Reading], seconds: TimeInterval) -> ArraySlice<Reading> }`. WS-C may ADD functions, never change these.
5. **Display throttling.** `SamplePipeline` publishes a `struct DisplayFrame: Equatable { var latest: Reading?; var tripStats: [SessionStats]; var recordingStats: SessionStats?; var extremes: Extremes; var publishedAt: Date }` at ≤ 5 Hz (`MeterManager.display`), plus `chart: ChartSnapshot` at ≤ 5 Hz. `MeterManager.latest` stays at 10 Hz (hero may use it only if it proves smooth; default to `display.latest`). `extremes` is assigned only when it changes.
6. **Formatter is pure.** No `mutating formatLive`. `enum UnitRange { case base, milli }` and `static func range(for value: Double, metric: Metric, previous: UnitRange?) -> UnitRange` (hysteresis: to milli below 0.95, back to base above 1.05). Callers keep `previous` in `@State`. `MetricFormatter` stays a value type; formatting uses `Locale`-aware `NumberFormatter`/`FormatStyle`, never `String(format:)` in views.
7. **Build system.** `ios/WattBench.xcodeproj` is UNTRACKED from git (`git rm -r --cached`, add `ios/*.xcodeproj/` to `.gitignore`); every build path runs `xcodegen generate` first (release.sh, run-on-phone.sh already do). Nobody edits the pbxproj. `project.yml` info.properties gets `CFBundleShortVersionString: $(MARKETING_VERSION)` and `CFBundleVersion: $(CURRENT_PROJECT_VERSION)`; `MARKETING_VERSION: "1.1"`. Add `UIBackgroundModes: [bluetooth-central]`. Add `SWIFT_STRICT_CONCURRENCY: targeted`. Do NOT add a time-sensitive entitlement; notifications use `.active`.
8. **Preferences additions (foundation):** `excludeDemoFromTrips: Bool = true`, `capacityUnit: CapacityUnit = .mAh` (`enum CapacityUnit: String, Codable, CaseIterable { case mAh, Ah }`), `showPeakLine: Bool = true`. `MeterManager.showAllDevices` remains the single owner of that setting (persisted by MeterManager); Preferences does not duplicate it.
9. **Frozen view inits** (streams may change bodies, never signatures): `DeviceListView()`, `SettingsView()`, `AlertsSettingsView()`, `AlertBanner()`, `RecordingStatusChip()`, `RecoverySheet(summary: SessionSummary)`, `DiagnosticsView()`. `ContentView` keeps calling `HistoryView()`; WS-C provides `typealias HistoryView = SessionsListView` (deleted in post-merge cleanup, not by WS-C). `Fmt` shim stays until post-merge cleanup.
10. **Frozen MeterManager surface additions:** `clearHistory()`, `devices: [DiscoveredDevice]`, `hasLastDevice: Bool`, `display: DisplayFrame`, `chart: ChartSnapshot`, `trips: [TripMeter]`, `extremes: Extremes`, `log/diagnosticsText`, `framesReceived/framesParsed/lastFrameHex/discoveredGATT` (existing diagnostics), `startDemo()`, `isDemo: Bool`.
11. **Diagnostics share.** Foundation switches `DiagnosticsView` to `ShareLink(item: meter.diagnosticsText)` and DELETES `ShareSheet` and the `URL: @retroactive Identifiable` extension from `HistoryView.swift` (HistoryView's own CSV share becomes a `ShareLink(item: url)`).
12. **Alerts wiring.** `AlertCoordinator` (stub in foundation) exposes `var onAlert: ((AlertEvent) -> Void)?` and `var onStopAndSave: (() -> Void)?`; `WattBenchApp.init` assigns `onAlert = { meter.addMarker(label: $0.title) }` and `onStopAndSave = { meter.stopRecording() }`. Foundation defines `struct AlertEvent: Identifiable, Equatable { let id: UUID; let ruleID: UUID; let title: String; let message: String; let firedAt: Date; let metric: Metric?; let value: Double? }` and `struct AlertRule: Codable, Identifiable, Equatable { var id: UUID; var name: String; var metric: Metric; var above: Double?; var below: Double?; var forSeconds: TimeInterval; var enabled: Bool; var notify: Bool }`. WS-E owns the bodies.
13. **Export.** `struct SessionExport: Transferable { let summary: SessionSummary; let loader: @Sendable (UUID) async throws -> Session }` (WS-C).
14. **Elapsed time rule.** Live counters show wall clock via `Text(timerInterval:)`; every stats/report surface shows `durationS` labelled "active" with the wall span secondary.
15. **Sparklines** are drawn with `Canvas`/`Path` from `summary.sparkline` (≤ 60 Floats), never a `Chart` inside a List row. The recorder maintains a 1 Hz mean-power array; `stopRecording` returns a `Session` whose `readings` may be empty when a journal exists (`sampleCount` is authoritative); `SessionStore.save` writes the manifest only when `samples.wbj` already exists.
16. **Storage layout (A2, for reference):** `Documents/sessions/<uuid>/manifest.json` + `samples.wbj`; legacy `<uuid>.json` files are migrated on first load by `LegacyMigration` (stored fields identical, sampleCount identical). Missing manifest → rebuilt from the journal header; missing samples → listed as "Samples unavailable"; unknown files ignored; sort by manifest `startTime` (no file timestamps, so no FileTimestamp privacy reason needed).

Simulators: each stream tests on its OWN simulator to avoid install races — WS-A: iPhone 17 Pro Max, WS-B: iPhone 17 Pro, WS-C: iPhone 17, WS-D: iPhone Air, WS-E: iPhone 17e.
